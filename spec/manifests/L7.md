  (`live/contracts.py`), so negative counts can reach the scorer.

INFERRED (builder's choices, B18 5 allows the formats)
- `days` spans the dates of rows that count toward an ad scored on at least one path (a skipped
  ad's rows are not "used").
- Ad name: the latest non-empty `entity_names["ad"]` over the ad's merged rows in date order.
- Ads in `CandidateScore.ads` and `skipped` are in ad-id order.
- Non-Beta reason string is `family <name>` (as the frozen sample uses).
- The negative check runs on the summed, rounded counts and comes before "no trials", so an ad
  with n < 0 or k < 0 always reads "negative counts".
- The unreadable reason is `<ExceptionType>: <first line of the message>`, cut at 200 characters.
- Page: a tail word (`tail_low`/`tail_high`) is shown only for surprised ads; rates, ranges,
  prior weight and shrinkage as percents with `rounding.percent_decimals`; ranges as `[lo, hi]`;
  ads surprised as `k / n`.
- `live score-priors` exits 1 when scoring raises (one line), 0 otherwise.
