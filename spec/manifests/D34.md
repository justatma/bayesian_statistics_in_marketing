## Open questions

1. D34 vs frozen P1: `test_P1_quarantine_fuzz` requires a Google Ads row with reported conversions above clicks to be quarantined. Implemented rule: keep above-clicks rows only when the row's attribution window counts view-through (Meta, LinkedIn defaults); quarantine under a click-only or per-conversion-action window (Google Ads default). Multi-event counting and reporting-date differences on Google Ads are therefore still quarantined. Lifting that needs either a frozen-test change or a registry field (`conversions_may_exceed_clicks` per platform) that the brief's channels.yaml scope did not allow.
2. Meta connector names: adding name fields to the insights request changes the recorded URL the frozen `meta_empty` replay matches; a separate names call broke six P8 unit tests that count exchanges. Names stay empty from the Meta API until `data/recordings/meta*` are re-recorded with the name fields, then add them to `INSIGHT_FIELDS`.
3. Objective from the APIs: F2 has no campaign `objective` / ad set `optimization_goal`, F3 has no `campaign.advertising_channel_type` or bidding fields, F4 has no objective type. `objective` is None on every connector pull until the packs list them.
4. LinkedIn campaign group, campaign and creative names need `/adAccounts/{id}/adCampaigns?q=search` and `/adCreatives?q=search`, whose shapes F4 leaves UNKNOWN.
5. F5 should be extended with the ResponseMetaData keys used here (verbatim), so they can enter `ga4.FIELDS`.
6. `diagnostics/run.py` (`_conversions`) feeds reported conversions into its CVR binomial PPC; a reported count above clicks there is outside this brief's files and may give an impossible binomial outcome.
7. Notice text `NOTICE_REPORTED_ABOVE_CLICKS` is a derive.py constant; requested `phrasing.yaml` key `notices.reported_above_clicks`. The `ga4_quality:` prefix is a ga4.py constant.
8. `Result indicator` remains in Meta `ignored_columns` (it maps to no export_map field); it is read through `objective_columns`.
