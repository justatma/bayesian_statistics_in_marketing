INFERRED

- Predictive check uses the exact Beta 99th percentile (scipy `beta.ppf(0.99)`) instead of simulated draws, so no draw count or seed is needed. The 0.99 level is taken from the registry key name `ceiling_q99`.
- The ceiling key is the last dot-segment of the parameter path. A ceilinged path with a non-Beta family is refused. A path without a ceiling passes and records q50/q99 where scipy has the family (beta, gamma, normal, halfnormal), else `{"ceiling_applies": 0}`.
- A refused prior stays unapproved and stays the client's latest proposal, so G8 holds until a newer proposal is approved. "Latest" is order in an append-only event log.
- `propose` strips any incoming approval (I10) and re-ids the record by content (`pr_<sha8>` of path, family, params, owner, version, rationale, source, promotion id). Re-proposing identical content keeps the stored record.
- Store layout: `<BAYES_DATA_DIR>/priors/records/<prior_id>.json` and `<BAYES_DATA_DIR>/priors/events.jsonl`.
- `resolve` returns a `pending_records` default unapproved instead of raising, so D23 item 2 (synthetic runs) still works; the fit raises G8 on client data.
- Default lag curve runs over a = 0..click-window days and is normalised by F(window) so `cdf[-1]` is 1, on the reading that platform-attributed conversions stop at the window's end. A window between table rows takes the next longer row's median; windows past the table or with no click window ("none", "property_setting", "per_conversion_action") take the 28-day row.
- Estimated curve is the empirical CDF up to the longest observed lag; orders with ordered_at before first_click_at are dropped.
- `n_lagged_conversions` on a default curve is the number of usable lagged orders found (below the minimum).
- An imported promoted record keeps its own approval; its stored owner hop is `vertical:<promotion_id>`; a record carrying a different promotion id is refused.
- `lag.model.notices(lag)` added as a helper, since `LagModel` has no notice field.

## Open questions

1. Resolved by D27.3: medians come from `bounds/lag/default_median_days@v1`.
2. No client-to-vertical mapping exists in core or the registries, so `resolve` records `vertical:unmapped` and skips the vertical hop. Imported vertical priors are stored but never resolved. `ClientConfig` would need a vertical field, or the promoted record would need to name its vertical.
3. Platform days-to-conversion report format is not in any facts pack. A non-empty `lag_report` without enough history raises ValueError; with enough history it is kept on record and unused.
4. Review item 7 conflicts with frozen `test_P7_unapproved_prior_blocks_fit`, which approves at wall-clock time and resolves at an earlier AS_OF. Ignoring approvals after `as_of` needs that test changed (AS_OF after the run date) or an injectable approval clock. Only proposal creation time is filtered now.
5. §5.3 C3 "immutable once used": the registry never rewrites an approved record, but it does not track use. A pending record is rewritten in place on approval.
6. Predictive check for paths without a plausibility ceiling (the D22 structural priors) has no refusal rule; they pass with their quantiles recorded.
7. D27.2 asks for the truncation to be documented in the notice. The notice text is `phrasing/notices/lag_assumed@v1` ("conversion lag assumed"), outside P7's files. If the disclosure must say "truncated at the click window", the integrator adds that wording to `phrasing.yaml`.
8. Right-censoring needs `as_of`. The frozen signature has none, so it is kw-only and P11 must pass it.
9. The exact call P11 must make: `lag = lag_model(platform, window_code, orders, None, timezone=client_config.timezone, as_of=as_of_date)`; for each entity and day, `mature_fraction(day, as_of_date, lag)` into `FunnelData.mature_fraction`; then add `lag_notices(lag)` to the run's notices and to every quantity derived from lag-adjusted data.
10. Unknown window codes now raise, including LinkedIn's registry default `90d_click_90d_view` and GA4's `property_setting`. With too little orders history those platforms get no lag model until the registry has a matching median row or a rule for codes with no click window.
