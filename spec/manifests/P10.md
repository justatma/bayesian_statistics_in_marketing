## Facts assumed

VERIFIED
- G5 rules: numbers at displayed precision, below-floor rate not a finding, marginal needs the caveat in the same sentence, comparatives match a `Comparison` and need decision basis marginal or estimable, plain causal verbs need randomized, "incremental" needs holdout, not-knowable items only in the not-knowable form (spec §10 C1, §14 I11, D2, D18 `ReportBundle.comparisons`).
- Rounding `percent_decimals` 1, `money_decimals` 0, `probability_decimals` 2; `caveat_marginal`, `not_knowable`, `not_knowable_block`, `watermark`, `evidence_plain`, `route_plain`, `causal_lexicon` (`registries/phrasing.yaml`).
- Guarantee prose from `guarantee_templates.yaml` only (I8, §4.8 `template_id`); diagnostics thresholds from `registries/diagnostics.yaml`.
- Render contracts C1-C7 (§12): G7 lists missing links; sampled quantities need a passing G3 report; below-floor block shows required against available; knowability section; plain-word evidence labels; diagnostics appendix or the conjugate phrase; narrative only with passing G5; client refuses synthetic, demo/internal watermarked (§4.13, I13).
- G7 raises `core.GateFailure` with gate "G7"; client synthetic refusal raises a non-`NotImplementedError` exception; not-knowable block shows `Feasibility.available` and `.required` as integers (test_P10 contract assumptions).
- `prior_registry.propose` takes a `PriorRecord` whose `resolution_path[0]` is `client:<id>` and drops any approval (P7 `registry.py`, §5.3).
- PDF only through the `pdf` extra (`pyproject.toml`); weasyprint is not installed here, so `pdf_path` is None.

INFERRED
- A number is matched only against quantities about the options and metrics the sentence names; a number that matches another ad's quantity is rejected.
- Non-quantity numbers that G5 accepts on exact match: comparison `p_best` and `p_exceeds_break_even` (as percent or 2-decimal probability; percent form refused in a sentence naming a metric), comparison and recommendation money, guarantee slot values, allocation shares, feasibility available/required as integers, horizon amounts.
- Comparative direction: for better/best/outperform/beat the first named option must have the higher `p_best`; worse/worst the lower. Weak comparatives (more, higher, lower, fewer, ...) count only with "than". An id-like token (letters with `_` or a digit) not known to the bundle in a comparative sentence is rejected.
- Decision basis for a comparative: the recommendations whose `economics_id` equals the comparison's; all must be marginal or estimable, and at least one must exist.
- Causal checks apply to all bundle quantities about the named options (all quantities if none named); holdout also satisfies plain causal verbs. Causal words matched exactly as listed in `causal_lexicon` (no inflections).
- G7 "valid provenance": at least one data pull, a funnel state unless deterministic, no G10 reasons, finite summary; every recommendation basis id and not-knowable id is a bundle quantity. Comparisons are rendered without a G7 trace (their options may be variant names, not quantity scope ids).
- Recommendation expected benefit/loss is shown only when every basis id is in the bundle. Guarantee slots not supplied are filled from the recommendation (horizon, assumptions, expected loss, top allocation option) and from the basis quantities (weakest evidence class, routes); if a slot is still missing the `statement_math` is shown instead of partial prose.
- A narrative block renders only if its carried gate is a passing G5 and a fresh `check_narrative` against the bundle also passes.
- Quantities listed in `knowability.not_knowable` are treated like below-floor ones (not-knowable block, never the estimate).
- `intake_prior_proposal` keys: client_id, parameter_path, family, params, rationale, author; optional evidence_refs, created_at (ISO 8601 with timezone), version (default "v1"). Source is always `ai_proposal`; unknown keys, including any approval field, are refused.
- HTML file name `report_<run_id>_<kind>.html` under `out_dir`; the template lives in `reporting/template.py` so it ships without package-data configuration.

## Open questions

1. The phrase "exact conjugate model; no sampler ran" is §12 C5 wording but not in `phrasing.yaml`; it is a constant in `reporting/render.py`. Move it to the registry?
2. Metric labels ("click-through rate", ...) and the G5 parser aliases are code constants in `claims/vocab.py`, and so are report section headings. Should `phrasing.yaml` carry metric labels (I6)?
3. `not_knowable_block` has a `{cost}` slot, but `ReportBundle` carries no cost of knowing (no `DesignAssessment`). The sentence with `{cost}` is dropped. Add the cost to the bundle (e.g. per not-knowable quantity), or keep dropping it?
4. ROAS has no display precision in `rounding`; `probability_decimals` is used. Add `ratio_decimals`?
5. `money_decimals: 0` renders a CPC of $1.25 as "1". Add a per-unit precision for per-click money?
6. The causal lexicon lists past-tense forms only ("drove" but not "drives"). Should the registry list inflections?
7. G7 does not trace comparison numbers to quantities, because `Comparison.options` can be variant names. Should `Comparison` carry its basis quantity ids?
8. Money quantities carry no currency (neither `Quantity` nor `ReportBundle` has one), so the findings table shows amounts without a currency code.
