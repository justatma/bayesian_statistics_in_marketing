## Facts assumed

VERIFIED
- Header aliases, `{currency}` slot, first alias canonical, case-insensitive trimmed match: `registries/channels.yaml` header comment, D20.
- Google Ads header detection by `Impr.|Impressions|Clicks` and dropping rows starting with `Total`: channels.yaml `preamble`, F1 §2.1 G5 (itself INFERRED in F1).
- GA4 `#` comment preamble: channels.yaml `preamble.comment_prefix` (F1 §4.1 A3 says UNKNOWN).
- UTF-16 encoding and `="123"` id cells: F1 §2.1 G6 (INFERRED in F1, from a Search Ads 360 page).
- Google Ads conversions may be fractional: F1 §2.3 G7.
- Meta currency in spend header: F1 §1.4 M13 (INFERRED in F1).
- No attribution column -> `manifest.attribution_window[platform]`; stale channel -> GateFailure G1 for that platform only; QQQ is unknown currency; Meta attribution values passed through; offsets normalized to UTC: acceptance_tests.md contract assumptions 2-6.
- GA4 currency from `DatasetManifest.currency`: D22 item 13. Switching cost YAML `{amount, currency}`: D22 item 14.
- Pull id `pull_<platform>_<sha8>`: D18.
- C8 typing and partial_truth formula: spec §5.1 C8.

INFERRED
- `channel_model` raises GateFailure G1 when stale (the test allowed either); `read_export` judges staleness at its keyword-only `as_of`, default `utcnow().date()`.
- `read_export` requires a manifest file entry with the same sha256 and platform, else G1 fails. A file with no header row, an undecodable file, two currencies in headers, or a missing required column also fails G1 rather than quarantining every row.
- Required columns: performance `date, entity_ids.ad, impressions, clicks, spend`; orders `order_id, ordered_at, value, refunded`; GA4 `date, sessions, purchases, revenue`. Conversions and revenue columns are optional on performance exports.
- When two columns map to one field, the column whose alias is listed earlier in the map wins; the other is ignored.
- Unmapped columns (including `ignored_columns`) are ignored; they remain visible in a quarantined row's `raw`.
- `entity_ids` keeps only account, campaign, ad_set, ad; `*_name` fields are dropped (core comment on PerformanceRow).
- Integers must match `-?\d+` and numbers `-?\d+(\.\d+)?`. Thousands separators and percent signs are quarantined, not parsed (F1 M17, G12 say formatting is UNKNOWN). `--` is an empty cell. Row currency codes are upper-cased before the ISO check.
- Negative revenue is quarantined like other negatives. Conversions above clicks is quarantined on Meta too, though Meta conversions can include view-through (C1 says quarantine).
- Currency per row: row column, else `{currency}` header slot, else manifest currency, else `load_economics(economics_id, path.parent).currency`. Column and header disagreeing is quarantined. With none: GA4 uses ISO `XXX` (no currency); performance and order rows are quarantined.
- Duplicate order_id: identical repeats keep the first and quarantine the rest; conflicting repeats are all quarantined.
- Orders: a timestamp without an offset is quarantined; `utm` is None when every utm cell is empty.
- C5: one `measurement_changes` entry per distinct (old window, new window, first day), naming the ads.
- Pull window for orders uses the UTC calendar date of `ordered_at`; performance and GA4 windows use the account-local row dates as exported.
- `timezone` is `UTC` for orders and for exports whose date header names UTC (LinkedIn `Start Date (in UTC)`); otherwise None.
- Pull id hashes (platform, file sha256, manifest_id), so re-reading the same file gives the same id. `account_id` is set when all performance rows share one account. `partial_truth` is False for GA4 and orders.
- ISO 4217 code set is hard-coded in `readers/currencies.py`; it is a standard, not a tunable.

## Open questions

1. The ISO 4217 list lives in code. Should it move to a registry (I6) so a code change needs no release?
2. Quarantine reasons and `measurement_changes` strings are code-built, not from `registries/phrasing.yaml`. They are diagnostics, not rendered prose; does I6 cover them?
3. `registries/channels.yaml` has `freshness_date: 2026-11-03` and `max_age_days: 90`. From 2027-02-01 every `read_export` (and the frozen P1 tests) fail G1 until the registry date is bumped.
4. The Meta header rules (`Results` objective-dependent, `Purchases` preferred, `Result indicator`, `Reporting starts`/`Reporting ends`) live in `read.py` as constants because channels.yaml states them only in comments. Proposed registry fields: `objective_dependent_headers`, `objective_indicator_column`, `period_end_column`.
5. `PlatformPull` has no notices field. Dropped summary rows and "conversions from objective-dependent Results only" go to the Python log, because the frozen tests assert `quarantined == []` and `measurement_changes == []` for `google_ads_canonical.csv` (has a Total row) and `meta_aliases.csv` (Results only). Proposed: `PlatformPull.notices: list[str]` in core.
6. GA4 with no currency anywhere yields `XXX`. Review item F12 asks for G1 failure or quarantine, but the frozen test reads `ga4_canonical.csv` with a manifest whose `currency` is None and no economics file, and asserts 4 rows and `quarantined == []`. Needs either a frozen-test change, `B.manifest(currency=...)`, or an `econ_00000001.json` fixture.
8. Thousands separators stay quarantined: F1 M17 and G12 leave number formatting UNKNOWN, so parsing `1,234` would be a guess.
9. `read_export` gained a keyword-only `as_of: date | None = None` (spec §5.1 signature unchanged for positional callers). The integrator should confirm or put it in the spec.
7. Requiring the file's sha256 in the manifest is stricter than any frozen test; P2 and P11 must list every export they pass in.
