## Facts assumed

VERIFIED
- Priors Beta(2,98) CTR, Beta(1,49) CVR, Gamma(shape 1, rate 1) conversions per dollar: `registries/priors/default.yaml` records, spec §14.
- compound-gamma k 2.0: `bounds.yaml` value.compound_gamma_k; `min_ads_for_coupling` 8: bounds.yaml coupling (D11).
- Quadrature tolerance 1e-10, joint draws 20,000: `decision_defaults.yaml`, §8.1 C2.
- Notice phrases (too_few_ads, lag_approx, platform_modeled): `phrasing.yaml` notices.
- Rate target 0.20 at 90%: `bounds.yaml` estimability.posterior_width (D10).
- G9 on unapproved economics or no loss tolerance: §8.1 C1, D16, contract assumption 15.
- CPA ~ InvGamma(α + n, β + spend): §7.2. Contribution per order = price − variable cost per draw: §4.10, D14.
- Oracle values: `tests/oracle/north_pier.py`, reproduced by quadrature before writing compare.

INFERRED
- FunnelState posterior for the conjugate route is `kind="samples"`, `family="conjugate"`, analytic hyperparameters flat in `params` (`<ad>.<param>.<name>`, flags `<ad>.flag.*`, `route.too_few_ads`), joint draws parquet columns `<ad>.ctr|cvr|cpa|cpm|aov` under `<BAYES_DATA_DIR>/funnel_states/`. `summary` describes the first column because the field is required.
- `state_id` hashes data, prior ids, seed and `created_at`, so each fit is a new immutable state.
- CVR lag adjustment: trials = Σ clicks·F(a); CPA exposure = Σ spend·F(a). Days with neither observed nor reported conversions give no CVR trials.
- Conversions: observed per day if present, else platform-reported (fractional allowed), which sets the platform-modeled flag.
- CPM: Gamma-Poisson on impressions per dollar with the PriorSet record `cpm_impressions_per_dollar` if supplied, else the reference prior Gamma(0, 0) (data only), flagged `flag.cpm_reference_prior`. The registry's pending CPM record is unapproved (I10), so it is not read directly.
- Order value with ≥ 2 positive order values: normal-inverse-gamma on log values under the reference prior (posterior σ² ~ InvGamma((n−1)/2, SS/2), μ | σ² ~ N(ȳ, σ²/n)); AOV per draw = exp(μ + σ²/2). Otherwise compound gamma on reported revenue per conversion: AOV ~ InvGamma(k·N, k·R) under a reference prior on the rate.
- CPC per draw = CPM / (1000·CTR). ROAS per draw = (1000 / CPM)·CTR·CVR·AOV (matches the dependence oracle).
- contribution_per_click at a fixed price = Beta(cvr) scaled by contribution per order and shifted by the observed CPC (spend / clicks), which is what the oracle's $1.25 and $500/340 imply. At a modeled price, or without observed spend and clicks in params, it is computed from draws.
- Evidence class: ctr, cpm, cpc delivery; aov commercially_realized only when it came from the orders file and an orders pull is among the state's pulls; everything else platform_attributed.
- derive writes sampled quantity draws to `<BAYES_DATA_DIR>/quantities/<quantity_id>.parquet`, one column named after the ad.
- compare values options at horizon × quantity for (ctr, impressions), (cvr, clicks), (contribution_per_click, clicks) only; option names are `scope.ids[scope.level]`.
- MC standard error reported is that of p_best, sqrt(p(1−p)/n), treating rows as independent.
- Mixed analytic and sampled options in compare draw the analytic ones with a seed from the hash of the option quantity ids.
- EVPI/EVSI return currency `XXX` (ISO 4217 "no currency") because DecisionProblem carries none; `assess` uses the economics currency.
- Test cost in `assess` is spend: volume × CPC draws (clicks), × CPM/1000 (impressions), or volume itself (spend); a days volume raises.
- Sample size uses the pooled-variance normal approximation, which reproduces 5,300.74.

## Open questions

1. Feasibility at derive. Quantity requires one, but the rate status belongs to P4. derive stamps `below_floor`, basis `quantity_precision`, reason "rate precision not yet assessed by floors/estimability (§6.1)". The pipeline must replace it with `quantity_feasibility`. If the status registry treats that stamp as published, I5 would read the later status as a move up.
2. Comparison types expected_value and expected_loss as Money. For CTR (clicks) and CVR (orders) objectives the amounts are counts in the target unit labelled with the economics currency. A unit field on Comparison, or a rule for pricing clicks and orders, would fix this. P4's decision_feasibility must not compare these against loss_tolerance.
3. p_exceeds_break_even is empty for CTR and CVR comparisons; a Quantity carries no CPC to set a break-even CVR.
4. No phrasing notice exists for the compound-gamma k disclosure (§7.2 "disclosed") or for the reference priors on CPM and order value. They are recorded only as params flags. A phrasing entry would let derive stamp them.
5. No approved priors exist for CPM or order value (the registry's are pending, I10). The reference priors used here are a modelling choice the owner should rule on.
6. Flags on sampled (NUTS) states: derive reads `<ad>.flag.lag_adjusted`, `<ad>.flag.platform_modeled` and the `<ad>.n.*` counts from `posterior.params`. P5 must write the same keys for the platform-modeled notice its tests require, and for n_events.
7. EVSI for non-signal designs (randomized volume tests) has no model linking volume to what is learned through the §6.3 interface; `evsi` raises ValueError without sensitivity and false_positive_rate. For the same reason `assess` searches no redesign (§6.3 C3) and never returns verdict "redesign".
8. The too-few-ads notice is stamped when the FunnelData has fewer than `min_ads_for_coupling` entities. A conjugate state built as the fallback's last step (P6) cannot be told apart from inside fit_conjugate.
9. The worktree started at 891e6aa, not ad8ffb6; it was reset to ad8ffb6 before any work.
