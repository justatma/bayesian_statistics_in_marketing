- `account_id` written at begin is `config.accounts.get(platform, "")`; the column is NOT NULL, so a missing account stores the empty string and the poll ends as a `ValueError` error row.
- An error before the pull (unknown zone name) still writes a poll: window falls back to the UTC date of `clock.now()`.
- Read-only open of a missing file raises `FileNotFoundError` before touching SQLite.
- `polls()` and `latest_poll()` sort on parsed `started_at` in Python, not on the text column.
- A prune failure inside `poll` is logged as a warning and does not change the returned record.

## Open questions

1. Error poll `recording_dir`: the polls row is written at `begin_poll`, before the outcome is known, and the store is append-only, so the stored value is the intended path `<record_root>/<client_id>/<poll_id>`. For a failed pull that path does not exist. The returned record matches the stored one. The frozen tests do not settle this; L3 should treat a missing directory as "no recording".
2. `poll` never raises on pull or row errors, but a failure of `store.begin_poll` or `store.finish_poll` itself propagates, since there is no store to record it in. Confirm this is the intended reading of C3.
3. Staging directories left by a crashed process (`.<poll_id>.recording-*`) name no poll, so prune leaves them alone forever. C4 says such directories are left alone and logged; confirm no sweep is wanted.
